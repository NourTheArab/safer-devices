# Source review required for every practical audit

[العربية](../ar/incident-review.md) · [Incident checks](../guides/incident-checks.md)

Review snapshot: **23 October 2026**. This is the source queue an agent must assess, not a package-install list. Check current content and applicability before running a probe or proposing a fix. “Read the link” isn't the same as “tested the device.”

## Required review record

For each applicable row, record privately: source URL, date accessed, advisory/release identifier, affected product/branch/platform, installed-artifact evidence, check performed and result, proposed repair and verification. If a source is blocked or unavailable, mark that fact and don't invent its contents. Use an already available independent primary advisory where possible, without bypassing access controls. Not applicable needs a reason based on actual inventory.

This queue isn't exhaustive: follow relevant references to original vendor notices for newly identified software, with a bounded source review. It doesn't authorize arbitrary network scans, repository access or running every linked tool. Extra tools, including alternative eMudhra or Mac-audit projects, need the same provenance, privacy, scope and approval review before use.

## Availability and review limits

During this update, the original gist, OpenJDK page, Next.js notice and Ruby notice couldn't be retrieved through the research tool. The current Dom repository and other primary sources above supplied available context; no unseen page's fixed-version claims are reproduced here. The Wardlatch repository's package manifest reported 0.1.8, but its npm version endpoint couldn't be retrieved, so this guide doesn't claim that package was verified or pin an installation to it. Verify availability and source/package agreement before execution.

These are documentation/source reviews, not independent code audits or endorsements of every linked tool. Keep a new review date for later audits. Don't use a 2026 snapshot as permanent clearance.
