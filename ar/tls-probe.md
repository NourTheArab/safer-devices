# فاحص شهادات للقراءة فقط

[English](../checks/README.md) · [فحوص الحوادث](incident-checks.md) · [المصدر](../checks/tls_probe.py)

أداة تشخيص صغيرة، لا برنامج إصلاح تلقائي. تستخدم مكتبة Python القياسية، وقد تستدعي ملف curl أو Node أو Bun موثوقًا ومحددًا صراحة. لا إصلاح أو تثبيت أو وصول للحسابات أو كتابة ملفات. حفظ التقرير بإعادة توجيه المخرجات قرار منفصل.

## قبل التشغيل

- قراءة المصدر و[قائمة مواقع الحادث](https://emudhra.we-have-a-problem.com/). تاريخ اللقطة **23 تشرين الأول 2026**.
- استخدام Python موثوق ومثبت مسبقًا، 3.9 فما بعد، لا بيئة مشتبه باختراقها. الخيار `-I -S` يتجنب تهيئة Python والموقع، ولذلك لا يفحص تلك التخصيصات أو الحزم الخارجية.
- الموافقة على الشبكة أولًا. المواقع وخادم DNS يمكنها رؤية عنوان المصدر وبيانات الاتصال. الشيفرة لا ترسل أسرارًا أو ملفات تعريف ارتباط أو تقريرًا.
- اتصالات Python وNode وBun مباشرة وقد لا تتبع وكيل HTTP؛ سياسة المؤسسة تُحترم. curl يتبع مسار البيئة والوكيل لكنه يتجاهل `.curlrc`؛ نطاق النتيجة كذلك. تخصيص الثقة القائم قد يؤثر في النتيجة.
- لا تجاوز للتحقق أو عناوين أهداف عشوائية أو شهادة عميل أو بيانات اعتماد أو رؤوس إضافية.

## تشغيل عميل مختار

من جذر المستودع، بعد موافقة الشبكة:

```bash
python3 -I -S checks/tls_probe.py --allow-network
python3 -I -S checks/tls_probe.py --allow-network --client curl --executable /usr/bin/curl
```

لـ Node أو Bun الخيار `--client node` أو `--client bun` مع `--executable` ومسار مطلق موثوق وموافق عليه. في ويندوز المسارات الخاصة بذلك الكمبيوتر. تشغيل Bun يعطّل تحميل ملفات البيئة والتثبيت الآلي. تهيئة Node السابقة قد تشغّل شيفرة؛ يلزم سياق تشغيل موثوق أو تبقى النتيجة مجهولة. الأداة لا تكتشف برامج عشوائية وتشغلها. الاعتماديات المفقودة فجوة حتى الموافقة على تثبيتها.

الضابطان السليمان: `github.com` و`emudhra.we-have-a-problem.com`. ضابط الرفض: `self-signed.badssl.com`. مواقع الحادث: اثنا عشر تركيبًا من DV/OV/EV وG3B/G3C وسلسلة مباشرة أو AAA، وموقعا `dv-g3b-noct-emudhra.we-have-a-problem.com` و`dv-g3b-aaa-noct-emudhra.we-have-a-problem.com`. القائمة الثابتة كاملة في المصدر. مطابقتها بالتنبيه الحالي لازمة؛ المواقع قد تتغير أو تتوقف.

Python وNode وBun مصافحة TLS فقط. curl يرسل HEAD بلا ضغط أو تحويل؛ لا حاجة لمحتوى HTTP. لكل عملية مهلة، لكن DNS من النظام قد يطول؛ قد يستغرق الفحص دقائق على شبكة بطيئة. JSON يعرض أسماء المواقع العامة الثابتة والحالات والنطاق فقط، دون نص أخطاء البرنامج الفرعي.

## النتائج والحدود

- خروج 0: `verified_for_tested_chains`، رفض الأربع عشرة بعد نجاح ضوابط السليم والرفض.
- خروج 1: `needs_attention`، قبول سلسلة حادث على الأقل بعد الضوابط.
- خروج 2: `unknown`، نقص أو خطأ أو فشل ضابط أو استدعاء غير صالح.

القياس لسلوك العميل والمسار الحاليين، لا للاختراق التاريخي أو الحظر الشامل للمفتاح أو أمان الجهاز. لا مقارنة لبصمات السلسلة الحية؛ انتهاء الصلاحية أو وسيط الحماية قد يفسران الرفض. لا تغطية لـ Apple URLSession أو pip/requests/certifi أو uv أو Java أو تطبيقات Go أو الحاويات؛ لكل منها صف مستقل.

مصادر الآليات: [Python SSL](https://docs.python.org/3/library/ssl.html)، [Node TLS](https://nodejs.org/api/tls.html)، [خيارات curl](https://curl.se/docs/manpage.html). توافق Bun يُقاس بنتيجة فعلية، ولا يُفترض من الإصدار.

التجربة الفعلية وحدودها في [سجل التحقق المؤرخ](probe-validation.md).

## اختبارات بلا شبكة

```bash
python3 -m unittest discover -s tests -v
```
