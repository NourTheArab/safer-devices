# نتيجة واحدة، إصلاح بموافقة، ثم إعادة فحص

[English](../guides/repairs.md) · [الفحص العملي](practical-audit.md)

اكتشاف المشكلة ليس نهاية العمل. المطلوب تغيير محدد لهذا الجهاز، وموافقة، وخيارات استرداد، وتنفيذ، ثم إعادة تحقق. الأمثلة ليست نصًا لإصلاح جماعي ولا تمنح صلاحية بنفسها.

## إعداد اقتراح قابل للمراجعة

استخدام [نموذج الموافقة](approve-one-change.md): المنتج أو الحساب والمسار المحدد، والدليل الحالي والتنبيه المؤرخ، والأمر أو خطوة الواجهة الدقيقة، والصلاحيات والأثر والنسخ والتراجع والتحقق المستقل. استبدال الأمثلة والحقول التجريبية قبل طلب الموافقة؛ الإصلاح غير المحدد لا يصلح للموافقة.

الأولوية للتحديث الرسمي، والتحقق من الناشر والتوقيع والبصمة من مرجع موثوق حيث يتاح. بصمة بجوار تنزيل مجهول لا تثبت المصدر. الجهاز المُدار أو الاسترداد غير المؤكد يحتاج قرار الإدارة المختصة.

## تحديث النسخة المتأثرة فعلًا

هذه **أمثلة لاقتراح**، بعد تأكيد أن Homebrew يدير الحزمة ومراجعة التصحيح الحالي. اختيار الصيغة المثبتة الفعلية؛ الأسماء تختلف حسب الفرع. لا تنفيذ للأمرين أو ترقية حزم غير مرتبطة افتراضيًا:

```bash
brew upgrade bun
brew upgrade node
```

التثبيت من مصدر آخر يحتاج محدّثه الرسمي. تحديث Node في الطرفية لا يصلح النسخة المضمّنة في تطبيق؛ تحديث التطبيق الموقّع ككل عبر ناشره. الأدوات الذكية الحالية تبقى بلا تغيير إلا بموافقة تحديث محددة.

في Go وJava: اختيار الناشر والتوزيع المدعوم والمعمارية، والتحقق من الملف الرسمي، وحفظ النسخة القديمة خارج الاكتشاف النشط عند الحاجة، وإظهار أمر التثبيت قبل الموافقة. لا نسخ لرابط أرشيف قديم. بعد التنفيذ: تأكيد اختيار البيئة وتجربة بناء وتشغيل غير حساسة عند مناسبتها، وإعادة فحوص الثقة وتحديد الخدمات المحتاجة لإعادة تشغيل. لا تفريغ لخصائص Java أو قيم بيئة Go.

البيئة المنتهية الدعم تحتاج انتقالًا مدعومًا واختبار اعتماديات. المترجم الجديد لا يعيد بناء البرامج القائمة. حصر خاص للتطبيقات التي بقيت دون معالجة.

## إصلاح الثقة بالشهادات بالدليل

1. تحديد العميل المتأثر ومخزنه الحقيقي، وحفظ نتيجة قبل التغيير مع الضوابط بشكل خاص.
2. تفضيل تصحيح من النظام أو التطبيق أو بيئة التشغيل أو حزمة الثقة المناسبة. في Homebrew قد يكون `brew upgrade ca-certificates certifi` اقتراحًا مناسبًا بعد إثبات النطاق؛ لا يغطي كل عميل.
3. إعادة اختبار العميل. استمرار الفشل يحتاج تحقيقًا، لا علامة نجاح مصطنعة.
4. عند غياب تصحيح عامل، شرح الاحتواء وأثره على الميزات. الحظر المؤقت للشبكة لا يصلح الشيفرة؛ إبقاء التطبيق متصلًا قرار يحتاج وضوحًا.
5. عند ضرورة تدخل محدود في مخزن الثقة، إعداد خطة قابلة للمراجعة وفق البصمات والتعليمات الأصلية الحالية. نسخ الحزمة وإعدادات الثقة القائمة، وبناء مرشح والتحقق منه قبل الاستبدال، وحفظ الإدخالات الأخرى والتراجع، وموافقة الإدارة. لا حذف جماعي للشهادات أو استيراد ثقة من لابتوب آخر.
6. إعادة الضوابط السليمة والذاتية التوقيع وكل سلسلة منطبقة، وتجربة HTTPS المعتادة. توثيق فجوات التطبيقات وإعادة الفحص بعد تحديث النظام.

لا يتضمن المستودع برنامج إصلاح شهادات عامًا، لاختلاف البيئات وجذور المؤسسات والحظر الحالي. عند الحاجة، المطلوب إعداد إصلاح خاص بالجهاز وقابل للموافقة، لا الاكتفاء بعبارة «تحديث الكمبيوتر». برامج الجهات المتخصصة تحتاج مراجعة وموافقة تشغيل أيضًا.

## إغلاق الدخول الوارد غير الضروري

في ماك، عرض **إعدادات النظام > عام > المشاركة > الدخول عن بُعد** وشرح أنه يتحكم بـ SSH الوارد. سؤال عن الحاجة، ثم الموافقة على الإيقاف والتعامل مع مصادقة آبل بشكل مباشر. إعادة فحص الواجهة والمنافذ، مع الحفاظ على إعدادات ومفاتيح الاتصالات الصادرة. مشاركة الشاشة والملفات قرارات منفصلة.

في ويندوز، مراجعة سطح المكتب البعيد وخادم OpenSSH وWinRM منفصلة مع القواعد والاعتماديات. إيقاف `TermService` ليس إصلاحًا عامًا مناسبًا. استخدام المسار الرسمي للخدمة المختارة، ثم إعادة تحقق الحالة والمنافذ والعمل المعتاد. [دليل ويندوز](windows.md).

الخادم المحلي الذي لا يحتاج عملاء خارجيين قد يناسبه الارتباط بالعنوان المحلي بعد مراجعة اتصالات الهاتف والشبكة الخاصة والحاويات. تغيير الارتباط وإعادة التشغيل يحتاجان موافقة. لا إغلاق منفذ بقتل عملية فقط.

## الحسابات والإضافات وتنظيف التطبيقات

| النتيجة | الإجراء الموافق عليه | التحقق والاسترداد |
|---|---|---|
| المصادقة غير مفعّلة | تفعيل وسيلة مدعومة عبر صفحة الحساب، مع بقاء التسجيل والاسترداد خاصين. | الصفحة تؤكد التفعيل؛ وجود وسيلة مسجلة لا يكفي. حفظ طريق استرداد متاح. |
| تطبيق متصل غير مستخدم | تسمية المنحة وصلاحياتها وأثر إلغائها، ثم إلغاء الموافق عليه فقط. | زوال المنحة أو الصلاحية المحددة. إعادة الاتصال قد تحتاج دخولًا مباشرًا. |
| جلسة غير معروفة | السؤال عن الجهاز والسفر والشبكة الخاصة، مع حفظ وصول موثوق حالي. | إلغاء الجلسة الموافق عليها ومراجعة الاسترداد عند الاشتباه. |
| إضافة غير لازمة | تحديد الناشر والملف والصلاحيات، واقتراح التعطيل قبل الإزالة. | تأكيد تعطيلها بالملف الصحيح واستمرار التصفح ومدير كلمات المرور. |
| تطبيق غير مرغوب | شرح الخلفية والاعتماديات والبيانات، وإزالة قابلة للاستعادة. | توقف التطبيق والعناصر المتفق عليها، وتوثيق البيانات المتبقية والتراجع. لا إفراغ للسلة. |
| صلاحية حساسة غير لازمة | شرح الميزة التي قد تتوقف قبل تعديل صلاحية واحدة. | الحالة المقصودة في الواجهة، والإتاحة والعمل الضروري ما زالا يعملان. |
| نسخة منفصلة أو غير مجرّبة | توصيل الوجهة يدويًا واقتراح استعادة ملف غير حساس لمجلد مستقل. | مطابقة المحتوى مع حفظ الأصل؛ تنظيف نسخة التجربة يحتاج نطاقًا. |

الموافقة العامة على التنظيف لا تشمل مدير كلمات المرور أو المحفظة أو المصادقة أو الأداة الذكية. الاشتباه بحزمة خبيثة يحتاج حفظ الأدلة وخطة حوادث قبل الإزالة. التحديث لا يستعيد سرًا سُرق.

## الحاويات وبيانات الاعتماد قرارات مستقلة

الاتفاق على محرك محلي وحمل محدد، ثم عرض الناشر وبصمة الصورة والتصحيح والاعتماديات والنسخ والتوقف والتراجع. الموافقة تسبق التنزيل أو البناء أو التشغيل أو الاستبدال. لا استخدام لـ `docker system prune` كتنظيف أمني. بعد التغيير: البصمة المنشورة والإعدادات المحددة ونتيجة الاعتماديات وتجربة التطبيق المعتادة.

القيم السرية تبقى بيد جهة الاستخدام. تحديد الخدمة والصلاحية والاعتماديات، وتأكيد وصول واسترداد عاملين قبل إلغاء قديم حيث يكون مناسبًا. التسرب المؤكد يتبع تعليمات الناشر من جهاز موثوق. لا نسخ للمفاتيح إلى التقرير ولا تدوير صامت لكل شيء.

## خاتمة بالأدلة والفجوات

جدول خاص: **النتيجة، والفعل الموافق عليه، وقبل، وبعد، وتجربة معتادة، والتراجع، والفجوة المتبقية**. توضيح إعادة تشغيل معلقة أو مخزن غير مفحوص أو نسخة منفصلة أو حساب خارج الجلسة أو تصحيح منتظر. التقرير خاص. أي إعادة فحص مستقبلية اقتراح، بلا تنبيهات أو مراقبة تلقائية دون موافقة.
